# Content Engine (map)

My content operating system. One shared brain (the database), with an engine per platform on top of it. LinkedIn first, YouTube next.
This file is a map, not a rulebook. Open only the files the job needs.

## Where things live
| Need | Go to |
|---|---|
| Who I help, the transformation, my content pillars (the ICP) | `database/foundation/pillars.md` |
| What's in the database and how each file is structured | `database/README.md` |
| How to find ideas (story types, prompts, momentum loop) | `database/ideation/` |
| How to write hooks and post bodies | `database/writing/` |
| Proven posts to borrow the shape of (tagged index) | `database/examples/index.md` |

| YouTube engine | `engines/youtube/README.md` |

## Standing rules
- Every content skill reads `database/foundation/pillars.md` first. If an idea doesn't fit a pillar and the transformation, say so before writing it.
- Ideas, hooks and formats come out 70/20/10: proven / adjacent / wildcard (see `system/wildcard.md`).
- When I correct you, add one line to `MEMORY.md` and fix the file it belongs to. Never correct the same thing twice.
- When a chat compacts, keep: decisions, pillar changes, file structures and templates.
- Scratch files go in the session scratchpad, never the repo root.
- Older context lives in the LinkedIn-Agent repo (voice profile, banks, course notes). Pull from it only when a file here points to it.
